# Excel reporting workbook specification

The application writes **one row per uploaded file** to a named Excel table in an
`.xlsx` workbook stored in the connected account's OneDrive for Business. D1 is
the source of truth; the table is a reporting copy that is kept up to date with
retries.

A ready-made workbook that meets this specification is in
[`docs/sample/UploadsReport.xlsx`](sample/UploadsReport.xlsx). You can rebuild it
with `python3 scripts/make-sample-workbook.py`.

## Requirements

| Requirement | Detail |
|---|---|
| File type | `.xlsx` (not `.xls`, `.xlsm` or `.csv`), stored in the connected user's OneDrive for Business |
| Named table | An Excel *table* (Insert → Table, "My table has headers"). The sample's table is called `Uploads`; any name works. You choose it in **Settings → Excel reporting workbook**. |
| Headers | Header names are matched case-insensitively, ignoring leading and trailing spaces. Column order does not matter. |
| Extra columns | Allowed. The app sends nothing for them (`null`), so formulas in calculated columns are preserved. |
| Body row | A table always has at least one body row. The sample has one empty placeholder row; new rows are appended after it, and you may delete the placeholder once real rows exist. |
| Edits | Avoid renaming or deleting required columns while sessions are live. If a column goes missing, submissions stay `excel_pending` and are retried until it is restored. |

## Standard columns (all required)

| Column | Type | Value |
|---|---|---|
| `submission_id` | text | Submission reference shown to the uploader, for example `K7Q2-M9XD`. All files from one submission share it. |
| `upload_session_id` | text | Internal ID (UUID) of the upload session. |
| `session_title` | text | Title of the upload session at the time the row is written. |
| `submitted_at_utc` | text | When the submission was started, as ISO 8601 UTC (`2026-10-18T14:03:22Z`). Kept as text so it reads the same in every Excel locale. |
| `original_filename` | text | The uploader's file name (path components removed). |
| `stored_filename` | text | The name in OneDrive, generated by the server: `YYYYMMDD_<reference>_<nn>_<safe-name>.<ext>`. **Unique per file; used to prevent duplicate rows.** |
| `file_size_bytes` | number | Size verified in OneDrive. |
| `content_type` | text | MIME type reported by OneDrive (or detected from the file signature). |
| `onedrive_folder_path` | text | Display path of the destination folder, for example `/Uploads/Event 2026`. |
| `onedrive_web_url` | text | OneDrive link to the file (opens for people who have access to it). |
| `processing_status` | text | `complete` once the file has been uploaded, verified and reported. |

## Field columns

Every form field configured on an upload session needs a matching column. By
default the column name is the field's **internal key**, for example:

| Field label | Internal key → column |
|---|---|
| Table number | `table_number` |
| Description | `description` |
| Name | `name` |
| Email | `email` |
| Reference number | `reference_number` |

To use a different header, set **Excel column** on the field in the session
editor. A field cannot map to a standard column or share a column with another
field. Number fields are written as numbers; all other values are written as
text.

A session cannot be published until **Check Excel mapping** passes, which
confirms that every standard column and every field column exists in the live
table. The same check runs again before every Excel write.

## Formula safety

Values that begin with `=`, `+`, `-`, `@`, tab, carriage return or `|` are
prefixed with an apostrophe (`'`), so Excel stores them as text instead of
evaluating them as formulas. The apostrophe is not displayed in the cell.

## Duplicate prevention

Rows are written in a single `rows/add` call per submission. If that call fails
or times out, the submission becomes `excel_pending` and is retried with capped
backoff (1 minute, doubling, at most 6 hours, 12 attempts). Before every retry,
the app reads the `stored_filename` column and skips files that already have a
row, so a write that succeeded but whose response was lost does not create
duplicates.
