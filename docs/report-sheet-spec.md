# Report spreadsheet specification (Google Sheets)

The application writes **one row per uploaded file** to a tab of a Google
Sheets spreadsheet in the connected Google account's Drive. D1 is the source of
truth; the sheet is a reporting copy that is kept up to date with retries.

The easiest way to get a correct sheet is **Settings → Create spreadsheet** in
the dashboard. It creates a spreadsheet with a tab called `Uploads`, a frozen
bold header row containing every standard column, and the field columns you
list (for example `table_number, description`).

Because the app uses Google's narrow `drive.file` permission, it can only open
spreadsheets **it created**. A spreadsheet you make yourself in Google Sheets is
invisible to it. Create the spreadsheet from the dashboard, then rename it, share
it or add tabs and formulas as you like.

## Requirements

| Requirement | Detail |
|---|---|
| File | A Google Sheets spreadsheet created by this app (Settings → Create spreadsheet). |
| Tab | Any tab. It is stored by its numeric ID, so renaming the tab is safe. |
| Header row | Row 1. Header names are matched case-insensitively, ignoring leading and trailing spaces. Column order does not matter. |
| Extra columns | Allowed. The app writes an empty string to them. |
| Edits | Avoid deleting required headers while sessions are live. If one goes missing, submissions stay `Sheet pending` and are retried until it is restored. To add a column for a new form field, type the field key into the next empty cell of row 1. |

## Standard columns (all required)

| Column | Type | Value |
|---|---|---|
| `submission_id` | text | Submission reference shown to the uploader, for example `K7Q2-M9XD`. All files from one submission share it. |
| `upload_session_id` | text | Internal ID (UUID) of the upload session. |
| `session_title` | text | Title of the upload session when the row was written. |
| `submitted_at_utc` | text | When the submission was started, as ISO 8601 UTC (`2026-10-18T14:03:22Z`). |
| `original_filename` | text | The uploader's file name (path components removed). |
| `stored_filename` | text | The name in Google Drive, generated by the server: `YYYYMMDD_<reference>_<nn>_<safe-name>.<ext>`. **Unique per file; used to prevent duplicate rows.** |
| `file_size_bytes` | number | Size verified in Google Drive. |
| `content_type` | text | MIME type detected from the file signature, or reported by Drive. |
| `drive_folder_path` | text | Display path of the destination folder, for example `/Events/Gala 2026`. |
| `drive_web_url` | text | Google Drive link to the file (opens for people with access to it). |
| `processing_status` | text | `complete` once the file has been uploaded, verified and reported. |

## Field columns

Every form field configured on an upload session needs a matching header. By
default the header is the field's **internal key**, for example:

| Field label | Internal key → header |
|---|---|
| Table number | `table_number` |
| Description | `description` |
| Name | `name` |
| Email | `email` |
| Reference number | `reference_number` |

To use a different header, set **Report column** on the field in the session
editor. A field cannot map to a standard column or share a column with another
field. Number fields are written as numbers; all other values are written as
text.

A session cannot be published until **Check report columns** passes, which
confirms that every standard header and every field header exists in the live
sheet. The same check runs again before every write.

## Formula safety

Rows are written with `valueInputOption=RAW`, so a submitted value such as
`=IMPORTXML(...)` is stored as plain text and never evaluated as a formula.

## Duplicate prevention

Rows for a submission are appended in a single request. If that request fails or
times out, the submission becomes `excel_pending` (shown as *Sheet pending*). It
is retried with capped backoff (1 minute, doubling, at most 6 hours, 12
attempts). Before every retry the app reads the `stored_filename` column and
skips files that already have a row, so a write that succeeded but whose
response was lost does not create duplicates.
